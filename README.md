# نظام تسجيل زوار المدرسة

تطبيق عربي RTL:
- تسجيل الحضور مع الاسم وصفة الزائر والجهة المراد زيارتها وسبب الزيارة.
- صفات الزائر: الاعتماد الأوروبي، ولي أمر، فريق من الوزارة، وأخرى مع حقل توضيحي.
- الجهات: إدارة المدرسة، مكتب الإرشاد الاجتماعي، مكتب الإرشاد الأكاديمي، مكتب الإرشاد الإداري، مركز مصادر التعلم، مكتب عيادة المدرسة، وأخرى مع حقل توضيحي.
- تسجيل المغادرة لاحقاً بإدخال الأسماء الثلاثة الأولى كما سُجلت عند الوصول؛ وإذا تعددت الزيارات النشطة المطابقة، يُطلب تحديد صفة الزائر.
- صفحة من نحن، ولوحة إدارة تعرض السجلات والإحصاءات حسب الجهة، مع البحث والتصفية وتصدير CSV.
- التوقيت المعروض: Asia/Bahrain.

## إعداد Supabase
1. شغّل كامل الملف `supabase/schema.sql` في SQL Editor. يمكن إعادة تشغيله لتطبيق أعمدة وخصائص التحديث.
2. من Project Settings → API انسخ Project URL والمفتاح العام anon/publishable.
3. من Authentication → Users أنشئ مستخدم الإدارة.
4. أضف المستخدم إلى قائمة المسؤولين:
```sql
insert into public.admin_users(user_id)
select id from auth.users where email = 'admin@school.example';
```

## التشغيل
يتطلب Node.js 18 أو أحدث:
```bash
npm install
cp .env.example .env
```
أدخل القيم في `.env`:
```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
```
ثم `npm run dev` وافتح `/admin` للإدارة.

## النشر
اربط المستودع بخدمة استضافة مثل Vercel أو Netlify. أمر البناء `npm run build` ومجلد النشر `dist`. أضف متغيري البيئة في إعدادات الاستضافة.

## الأمان
- الزائر يستطيع تسجيل الحضور فقط ولا يستطيع قراءة السجلات.
- تسجيل المغادرة يتم عبر دالة قاعدة بيانات محدودة الصلاحية تبحث عن الزيارة النشطة بالاسم والصفة عند الحاجة، ولا تمنح الزائر صلاحية قراءة السجلات.
- مطابقة الاسم والصفة وسيلة لتحديد السجل وليست إثبات هوية قويًا؛ ينبغي أن تكون إجراءات الاستقبال المدرسية هي المرجع عند الالتباس.
- قراءة السجلات محصورة بحسابات الإدارة المدرجة في `admin_users` عبر RLS.
- لا تضع مفتاح `service_role` في المتصفح أو GitHub.
